# 线上加载失败排查与改进

最新v0.5.2针对PNG图片未进入受控下载通道、首次渲染就撤销加载页的遗漏，恢复完整加载页及关键纹理就绪屏障。见 [红黑棋盘根因分析](texture-loading-root-cause.md)。

v0.4.5起针对“引擎JavaScript仍整包下载”的断点继续改进，见 [启动与资源交付架构](loading-architecture.md)。下面保留各轮证据与修复范围，不能把早先版本的本地测试当作当前线上成功的证明。

2026-10-15，在已部署页面的控制台中定位到 `/data/city-overview.json` 返回响应头200，但随后 `ERR_CONNECTION_CLOSED`，页面报 `TypeError: Failed to fetch`。原启动代码把该文件放在必需数据的 `Promise.all` 中；一份远景建筑数据失败，会让整个主场景初始化退出。

HTTP复测该文件确实存在，Content-Type为application/json，Cloudflare缓存HIT且启用Brotli。一次完整读取1,858,263字节约85秒，另一次读取超时。这证明传输有明显慢速/中断现象，不能仅因200状态判断文件已经完整下载；这些记录也不足以单独认定是Cloudflare、运营商、本机代理或浏览器扩展中的哪一环关闭连接。

Zotero/inject连接错误、`Resend failed ... uniqueContextId not found` 不来自本仓库源码。后者更像调试/扩展工具重发请求时的执行上下文问题，不是入口JS存在语法错误的充分证据。排查时应区分扩展提示与应用本身的fetch失败，可使用不加载扩展的浏览器窗口及另一条网络对比。

首轮v0.4.2代码改进：

- `asset-loader.ts` 对JSON、地形二进制和Havok二进制的整个响应体读取设置总超时，最多尝试两次，重试不复用浏览器缓存；永久404不重复请求。响应头200后的中断也会重试。
- 栈桥近景先启动。全域远景建筑、区域道路/分块索引、区域海岸小地图、地铁线路在主场景启动后独立后台加载；任一任务失败不再使主场景退出。
- 后台任务保留已加载内容，失败项目显示补载按钮，再次点击只补载未成功的项目。
- 首屏显示地图下载、真实高程、地标生成、物理引擎下载、碰撞初始化等实际阶段；必要资源失败显示具体路径和重新加载入口。
- Havok使用已完整下载的wasmBinary初始化，高程文件校验实际字节数，避免不完整二进制被当作有效数据使用。

这些改动提升慢网和中断时的恢复能力，不能修复底层网络链路。v0.4.2仍把基础地图、高程及物理引擎作为首屏前置下载，后台尚未完成时全域内容会逐步出现。

验证：32项测试通过，包含200响应正文中断和读取正文超时；0.4.2生产构建与Wrangler部署预检通过。生产构建的浏览器故障模拟中，远景建筑接口连续两次返回503后，主场景正常显示、Havok启用，后台状态为3/4并显示重试按钮；点击后补载至4/4，按钮自动隐藏。此模拟验证应用恢复能力，不代表线上网络故障已消失。本次本地构建入口为 `index-DjX-LEZq.js`。

## v0.4.3：基础地图传输中断

用户进一步确认页面显示“无法完整下载 /data/scene.json”。HTTP复测线上HTML已经引用v0.4.2入口 `index-DjX-LEZq.js`，所以这次不能归因于未发布上次修复。直接连接的scene.json在约28秒内只收到458,752字节，region.json约26秒只收到32,768字节；入口JS、Babylon和WASM也存在慢速/读取超时。该探测设置了时间上限并主动结束部分读取，不能把每个探测的主动结束都视为服务器断连。结合用户的终端报错，可以确认基础资源传输仍不稳定，但不足以断言是哪一段网络造成。

本轮改进：

- Vite插件在构建时自动gzip压缩基础地图、区域大文件、4份DEM与Havok，并拆为最多32 KiB的静态二进制片段，内容哈希URL随资源变化。scene.json保持原始1,730,630字节，传输为418,788字节、13块，不减少建筑或地理精度。原文件仍保留供来源查看及兼容回退。
- 片段最多4路并发，每片最多尝试两次、每次30秒上限；验证片段长度和解压后长度。失败时复用已成功片段；内存缓存有界，并通过`public/_headers`为内容哈希片段配置不可变缓存。gzip浏览器解压不可用时回退普通原文件下载。实现见`src/asset-loader.ts`和`scripts/asset-chunks.mjs`。
- Havok不再阻塞观景和飞行，作为第5项后台任务准备。碰撞初始化失败可补载，物理未就绪时点击步行会显示说明，准备完成后启用。
- HTML自身提供带回澜阁图标的启动画面，启动脚本未完成时也有可见状态；显示下载KiB、完成片段数、重试和阶段记录。脚本失败可见报错，等待超过20秒会提供重新加载入口。
- 新增`favicon.svg`、`favicon-32.png`和`apple-touch-icon.png`，使用回澜阁双层金色屋顶、栈桥与海浪，加载页和品牌标识同步使用。

验证：35项测试通过，生产构建及Wrangler部署预检通过。生产包浏览器故障模拟中，scene的首个分块返回200但正文被截断，自动重试后成功进入场景；Havok一个分块连续两次返回503时，观景正常，显示步行物理待补载；点击重试后后台5/5完成，Havok启用，实际点击步行可进入。浏览器未记录应用错误。验收截图保存在本地忽略目录`artifacts/startup-v043-physics-deferred.png`与`artifacts/startup-v043-recovered.png`。

分块提升中断恢复能力，不能保证任意网络下的首屏速度；三维引擎JS和材质图片仍需通过原链路下载。若部署后所有静态资源依然很慢，需对比另一条网络以及Cloudflare边缘/域名链路，不能通过增大前端超时彻底解决。

更新后需提交并推送代码，再由Cloudflare构建发布。v0.4.3的加载详情会显示版本号，HTML入口文件约1.85KB；后续v0.4.4检查发现它并未真正独立于大包，原因和修复见下节。不能只重试旧提交就期望启动逻辑改变。本机Wrangler未认证，未代替用户发布到线上。

缓存头格式依据[Cloudflare Workers Static Assets Headers](https://developers.cloudflare.com/workers/static-assets/headers/)；所有分块由现有`npm run build`自动生成，不需要在Cloudflare另行安装Python或解压插件。

## v0.4.4：入口文件小，但静态依赖仍然很大

用户截图显示v0.4.3停留在HTML初始文案“正在下载启动程序”，日志没有bootstrap.ts写入的“正在加载三维引擎与场景程序”，因此不能继续归因于scene.json；此时资源加载代码根本没有执行。

检查实际生产包发现：index-DD27rqqQ.js开头静态导入babylon-Cluqx-_n.js中的Vite preload helper。Rollup原先的manualChunks函数只显式选择Babylon模块，但默认行为也把这些模块的依赖合入手工chunk，包括共享的预加载辅助代码。于是入口必须等待约1.83MB的引擎包下载、解析与执行，之后才有机会更新页面。这是上一轮未覆盖的构建依赖问题；只检查入口文件大小或模拟JSON失败都无法发现它。

修复与设计边界：

- 设置output.onlyExplicitManualChunks=true，只把明确选择的Babylon模块合入引擎包。加载辅助代码从引擎包分离，HTML不再提前modulepreload整个Babylon。
- 共享预加载辅助函数进一步独立为约1.11KB的loader-runtime，入口本身约2.38KB，合计约3.49KB；引擎只依赖这个稳定辅助包，避免启动页文案修改通过反向依赖连带更换整个引擎包的缓存URL。
- 新增scripts/startup-graph.mjs构建守卫，遍历生产入口的所有传递静态依赖，禁止其中出现Babylon模块，并限制总量24 KiB；三维引擎保留为动态依赖。3项回归测试分别覆盖“入口很小但辅助模块间接指向引擎”、允许动态依赖、传递依赖预算。
- 启动程序先报告“已就绪”，随后加载三维程序；原生模块请求长时间无响应时显示网络慢的说明和重试入口，失败保留具体路径。原有大数据分块、后台物理与区域补载继续保留。
- 网站图标从加载页及页面品牌区移除，恢复QD文字；补充真正的favicon.ico，6种分辨率，仅通过HTML head图标链接使用。SVG/PNG仅作浏览器和触屏书签的兼容格式。
- 对带内容哈希的/assets/*配置不可变缓存，减少重复访问下载；HTML不配置永久缓存。

本轮修复保证加载器可以先运行，不等于消除网络中断。引擎主体仍约1.83MB（gzip约430KB）；首次访问下载它是进入三维画面的必要成本。如果该资源通过当前线路仍反复中断，应对比访问网络或选择更靠近实际访客的静态托管/CDN，继续增大前端超时并不能修复传输链路。

验证：38项测试、生产构建及Wrangler部署预检通过。生产入口为index-DUTc3QW5.js，只静态依赖loader-runtime-BXl3LOEh.js；HTML不再预加载Babylon。浏览器模拟Babylon返回503时，启动日志先显示“启动程序已就绪”，然后显示中文下载失败和资源路径；恢复资源并点击重新加载后进入主场景，后台5/5完成、Havok启用。页面body没有favicon图片，品牌为QD；favicon.ico包含6种尺寸。本轮仍为本地修复，需经用户现有Cloudflare构建流程发布。
