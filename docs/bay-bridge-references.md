# 胶州湾大桥资产：资料、位置推定与模型限度

资料核验日期：2026-10-13。仅新增独立资产模块和派生数据，供主场景接入。

## 水平几何与地理坐标

`public/data/bay-bridge.json` 来源于本项目留存的 `sources/shandong-latest.osm.pbf`，Geofabrik / OpenStreetMap 数据时刻为 2026-10-11T20:21:06Z。标注 © OpenStreetMap contributors，ODbL 1.0。原始 PBF、研究 PDF 与照片截图位于 `sources/`，不作为浏览器运行资源发布。

投影与既有栈桥数据一致：`+proj=aeqd +lat_0=36.0603 +lon_0=120.3163 +datum=WGS84 +units=m +no_defs`。原点 WGS84 经度 120.3163、纬度 36.0603；`x` 向东，`z` 向北，单位米。没有人为拉伸 OSM 线形。

提取了 35 条具有 bridge 标记的道路：主线 S85 共 13 条、连接匝道 17 条、红岛 S8511 连接线 2 条、胶州 S8512 连接线 3 条。匝道依 OSM 共享节点连通性选取，保留名称、车道数、layer、ref 与其他 tags。以 2,400m 空间单元按材质合批生成；不是将每根桥墩做成独立 mesh。

OSM 两幅主线形成独立连续链，分别约 25,615m、25,574m，平均 **25,594.431m**。该值仅是本次 bridge-tagged ways 的测量范围，**不能代替大桥运营全线长度**。运营方 2025 年文件的主线长度为 26.737km，包含陆域引桥等；常见早期 26.707km 与本数据采用的分类、起终点口径也不同。模型不为凑官方长度而缩放地理数据。

两个实际 OSM 车道中心保持分离；普通桥面每幅 17.5m 是官方 35m 总宽的一半推定，`estimatedWidth: true`。航道桥宽度另依据技术论文：沧口、红岛每幅钢箱梁外缘宽 24m，在模型中以 100m 过渡接普通桥面。大沽河论文给总宽 46m；依据 OSM 两幅中心间距约 26.7m，模型每幅暂取 20m，并添加横向连接箱，属于估算。宽度模型没有把两条 OSM 平行路线分别铺成 35m。

## 三座航道桥及依据

| 航道桥 | 本版结构 | 有依据的跨度/尺寸 | 高程处理 |
| --- | --- | --- | --- |
| 沧口 | 双幅分离、纵向双塔、每幅 H 形塔、稀索斜拉 | 总长 600m，主跨 260m，塔柱横距 20.6m；运营方给塔底高程 5m、顶高程 110m、塔高 105m | 模型按塔底 5m、高 105m；桥面暂取 46m |
| 红岛 | 双幅分离、纵向独塔、每幅 H 形塔、稀索斜拉 | 两跨 120+120m；模型 24 根斜拉索，H 形横距暂沿用 20.6m | 塔高 65m、塔底 5m尚未核实到权威竣工高程，显式估算；桥面暂取 31m |
| 大沽河 | 单个中央独柱塔、自锚悬索、中央空间主缆与垂直吊索、双边钢箱梁和横向连接箱 | 总长 610m，跨度序列 80+190+260+80m，主跨 260m，官方塔高 148.7m | 148.7m 暂直接置于海面基准，未取得承台/海面统一基准；桥面暂取 53m |

模型没有把三座航道桥都制作成同一种通用斜拉塔。桥塔矩形截面、横梁厚度、悬索线形、缆索直径、吊索与横箱的 12m 布置、承台外形、路灯、蓝色护栏和原创路标均为低面数视觉解释，不能作为竣工测绘或结构计算模型。大沽河纵向主塔以跨度顺序推定在航道桥中心偏 -35m；该方向和实际塔位仍需竣工平面坐标进一步校准。

沧口旧百科常见 82.5m 塔高，本版采用直接可核实的运营方资料 **105m 塔高 / 110m 顶高程**，不再采用该旧数值。

普通海中桥墩采用 60m 周期（运营方事实），西岸实际存在 50m 滩涂跨径，本版暂未逐跨识别。普通桥面 18m、各航道桥桥面高度、渐变坡度和匝道 layer 对应的 4.7m 层差均为估算，metadata 明确标注。地形与桥面相交时以 `sampleHeight + 6m` 保持视觉净空。普通墩避开航道主跨区域；没有在主航道内布满等距普通墩。

## 航道定位方法与限制

[中国海事局 2026-06-0182 海图改正](https://pnp.chart.msa.gov.cn/CorrectionPdf/Download/bf0d499e-5e6d-4219-b811-4a62f0f3c62c?y=2026)公开沧口桥墩灯点：36°10.26′N / 120°20.07′E 与 36°10.26′N / 120°19.89′E。这是**桥墩灯坐标**，不是主塔中心的实测坐标。本版将两个灯点投影至两幅 OSM 路线平均轴线，取沿线投影距离中值作为沧口航道桥中心定位。

[运营方 2025-05-31 养护采购公告](https://www.sdhsg.com/article/67308)给出沧口 K36+930–K37+530、红岛 K47+490–K47+730、大沽河 K51+690–K52+300。以这三段中点的相对桩号距离，在真实 OSM 平均轴线上从沧口锚点向西推算红岛与大沽河。该方法为合理推定，全部 `estimatedTowerPositions: true`，不声称拥有测绘级塔位。红岛航道桥与东侧的红岛海上互通不是同一位置。

## 重建与验证

在项目目录运行：

```powershell
python scripts/probe-bay-bridge.py
python scripts/extract-bay-bridge.py
node scripts/verify-bay-bridge.mjs
npx tsc --noEmit --target ES2022 --module ESNext --moduleResolution Bundler --lib "ES2022,DOM" --strict --skipLibCheck src/bay-bridge.ts
```

脚本使用 Python requests/pyosmium/shapely/pyproj，Node 验证执行真正资产构建代码与 Babylon ComputeNormals，纹理与渲染 mesh 使用无浏览器 stub。检测：35 条道路全为有限坐标、正长度，主线 25–27km 范围；生成 mesh 全部 vertex/normal/index 有效，桥面向上；细节切换和 dispose 正常。

本版验证结果：94 个合批 mesh，17 个桥面 collision mesh，458,616 vertices，152,872 triangles，其中桥面 4,022 triangles。桥面 normal.Y 最小 0.998755；高度范围 -1.7–148.7m。测试机器 Node 构建约 170–190ms，仅反映几何生成耗时，不是浏览器帧率或 Havok 性能承诺。

`setDetail(distance, focus?: Vector3)` 在相机目标距离大于 9km 时隐藏护栏/路灯、车道标线和路标；传入地理焦点时，按每个 batch 完整 XZ 包围盒的最近距离裁掉焦点 max(8km, 视距×1.5) 外的所有桥 mesh，全域缩小时保留完整线路，不按包围盒中心误藏长段的近端。三个航道桥各自合批，避免全湾塔索被一个巨大包围盒牵连。重复桥墩、梁、桥面和索不进入动态阴影列表，仅三个航道的局部塔批次投影；所有模块 mesh 的 `metadata.name` 统一为胶州湾大桥，具体构件名在 `metadata.structure`。

物理对象由调用方按区域需求创建，不在模块内对全部桥墩生成 Havok 刚体。

浏览器外观校正：海中普通墩底伸入海面以下1.7米，避免将渲染用2.4米水格地形底线误作陆地；H塔承台横向宽度与两塔柱保持一致。斜拉索视觉半径0.28米为屏幕可读性估计，未视为施工尺寸。航道导航采用斜向低俯视角以展示横梁与索面。动态阴影仅提交当前焦点附近的构件。
